# Design: figma-theme-modes

## Context

Upstream facts verified 2026-08-26 against official Figma docs (developers.figma.com MCP tools page, REST API forum):

- No official Figma MCP tool takes a variable-mode parameter (`get_design_context` / `get_screenshot` / `get_variable_defs` / `download_assets` all mode-less); desktop MCP reflects the current selection/view, so fetched payloads carry whatever mode the file/frame currently renders.
- REST image rendering follows the mode set on the page/frame in the file; REST Variables API exposes `valuesByMode` per variable.
- Industry practice: semantic design tokens per mode (W3C DTCG-style), per-theme asset exports.

## Goals / Non-goals

- Goals: systematic light/dark (+N) support inside both skills; measurable per-mode contract; per-theme verdicts.
- Non-goals: changing single-theme default behavior; a separate skill; hardcoding MCP internals (no mode param exists to hardcode).

## Decisions

1. **Embed in both skills** (not a new skill): theme handling is a dimension of implement/verify lifecycles, not a standalone phase; referencing hosts stay thin.
2. **Explicit-scope gating**: multi-theme expansion runs only when the user requests it; default single-theme + anti-drift rules unchanged. Prevents speculative scope growth and token bloat.
3. **Per-mode expected values** resolve via variable `valuesByMode` when the channel exposes them, otherwise switch the file/frame mode (or use the per-theme frame) and re-fetch. Matches upstream reality (no mode parameter).
4. **Per-theme assets** must be design-provided exports (second export from the switched mode or per-theme frame); one export + invented recolor stays forbidden — consistent with the existing mask-recolor ban.
5. **Theme mechanism mapping**: multi-theme implementations map variables onto the project's theming mechanism (CSS custom properties / tokens / `data-theme` / `prefers-color-scheme`) instead of duplicated hard-coded literals; shared geometry/type values stay single-valued.
6. **Verify per theme**: identify the UI's switching mechanism, switch, measure per-mode rows under each theme as separate verdicts; report per theme; overall pass requires every measured theme within tolerance.
7. Versions bump minor (1.0.1 / 1.0.0 → 1.1.0); descriptions add Chinese + English theme triggers within the length limit.

## Risks / Mitigations

- Upstream may later add a mode parameter → instructions are intent-level ("resolve per-mode values via the channel's mode support, e.g. valuesByMode or mode-switched re-fetch"), so a future parameter slots in without contract change.
- Token bloat in SKILL.md → gating wording ("single-theme requests skip per-theme expansion"); details live in reference.md tables/checklists.

## Migration Plan

Pure additive markdown edits; no tooling or schema changes; index regenerated by the existing pre-commit flow.
