# skill-creator intent capture — tech-research-workflow (v1.0.0)

Answers per skill-creator "Capture Intent"; interview inputs are frozen by the queue card, recorded here rather than re-asked (queue-child auto run).

1. **What should this skill enable the agent to do?** Run an evidence-driven technology/competitor research engagement end-to-end: understand the requester's own business and codebase, extract first-hand evidence from shipped competitor features (runtime forensics, evolution curves, same-track incidents), map competitor designs onto own constraints in three tiers, and assemble a layered, decision-ready report family — with a lean path for single-question research.
2. **When should it trigger?** User phrases: 「技术调研」「竞品调研」「竞品分析」「技术调研报告」「调研报告」「竞品实测」/ tech research, competitor research, competitive analysis, technology research report — when the ask is design-shaping research producing a report, not a single lookup. Boundary: NOT for single-question web lookup (`research` / `effective-web-research`), known-bug upstream routing (`known-issue-research`), or rewriting an existing design doc into a review doc (`tech-review-doc`).
3. **Expected output format?** Full path: report family (architecture main doc / per-area details / evidence compendium / summary / one-page decision memo / review agenda with A-decisions, B-confirmations, C-must-test). Lean path: one-page evidence-linked answer. Evidence standards apply to both.
4. **Test cases?** Yes — the output behavior is partially objectifiable (does the agent run steps in order, classify all elements, bind claims to evidence). This environment cannot run the full subagent eval loop; a lightweight 3-prompt batch is recorded in `eval-lightweight.md` per repo spec `skill-creator-eval-harness` (trigger + boundary + gate coverage), full loop deferred to a follow-up card.
5. **Authoring constraints (repo铁律)**: English body; Chinese triggers in single-line quoted description ≤1024 chars; `dependencies: [effective-web-research]` with abort paragraph; platform-neutral intent phrasing (no tool enumeration); de-identified placeholders only; positive phrasing; no version-history notes; SKILL.md <500 lines with depth in reference.md.
