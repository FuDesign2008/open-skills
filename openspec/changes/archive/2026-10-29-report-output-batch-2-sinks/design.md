# Design: 第二批报告产物接入

## Context

第一批交付了格式契约、共享渲染器与产物注册表。三个报告类 skill 仍只有模板、没有 sink，注册表标为 `sink 待定`。本批为它们定义落盘路径并接入既有契约。

## Goals / Non-Goals

**Goals**

- 三个 `sink 待定` 清零，报告可归档、可评审、可派生 HTML
- 落盘路径与「按需分层」都可机械核验
- 不新增与既有契约并行的第二权威

**Non-Goals**

- 不改报告内容模板
- 不处理 `perf-optimize-workflow` 的 `BENCHMARK.md`（已登记为 `dual`）
- 不为报告引入索引页或站点生成

## Decisions

### D1：子目录用角色名而非 skill id

用户确认的预览是 `diagnosis/`、`research/`、`evolution/`。角色名比 `essence-diagnosis/` 更短、更贴合产物语义，也让未来同类报告有稳定归属。

代价：与用户最初说的 `<skill>` 字面不同。设计上认定为「稳定子目录」规则，契约正文显式列出三个目录名，不保留占位符。

### D2：`Layers:` 行让「按需分层」可核验

「按需」若只写成散文，只有 AI 临场判断，违反门禁输入可核验原则。

改为：`main.md` 在代码围栏外用**恰好一行** `Layers: <csv>` 记录本次实际产出的层；层名到文件的映射固定；未记录的层不要求存在；没有可选层时写 `Layers: none`。

这样验收可以机械执行：读 `main.md` 的一行 → 查表 → `test -f` 每个文件。

### D3：`evolution/` 与仓库既有忽略规则冲突

仓库 `.gitignore:163` 的 `**/evolution/` 会忽略 `docs/reports/evolution/`，使台账真源无法入库。

在临时仓库实测三种组合后确定最小可行规则集，且顺序固定：

```gitignore
**/evolution/              # 既有
!docs/reports/evolution/   # 新增：解锁目录
docs/reports/**/*.html     # 新增：忽略派生页（必须在负向规则之后）
```

实测结果：`ledger.md` 不被忽略、`ledger.html` 被忽略。把负向规则放在 `**/evolution/` 之前无效（目录仍被排除）。

### D4：台账单文件滚动，诊断与调研按次新建

- 台账是跨期的比较基线，必须累积在同一文件，否则失去滚动窗口的意义。
- 诊断与调研是单次事件，按 `<YYYY-MM-DD>-<topic>` 新建。
- 同日同题**再次运行**时追加 `-2`、`-3`，避免静默覆盖；同一次运行内的重写（调研的首版探针）仍写回本次目录。

### D5：每次写入都重新派生

诊断与调研的派生页在同一次运行内可能被重写（调研报告首版是探针）；台账每次复盘都会更新。因此「写入或更新真源后 MUST 重新派生」写成通用要求，而不是只在台账上提。

### D6：注册表产品名与规格统一

注册表原为「演化复盘 ledger」，规格为「演化复盘台账」；实现时统一为后者。

## Risks

| 风险 | 影响 | 缓解 |
|---|---|---|
| 忽略规则顺序写反，派生 HTML 入库 | 中 | 契约固定顺序；契约测试断言 `ledger.html` 被忽略、`ledger.md` 不被忽略 |
| `Layers:` 行被模板示例误匹配 | 中 | 要求围栏外、恰好一行、以 `Layers:` 开头；测试同时断言文件存在 |
| 调研目录随时间膨胀 | 低 | 按日期分目录；不引入索引页 |
| 台账并发更新冲突 | 低 | 单文件滚动，冲突在 git 层可见；不引入锁 |
| 三个宿主遗漏派生步骤 | 中 | 每个宿主有对应场景与契约测试断言 |

## Migration

一次完成，无分期：三个 skill 各自的 sink 与派生、`.gitignore`、注册表、契约测试同批合入。
