# fix-verify-evidence-ui-screenshot — Delta Spec: runtime-verification-discipline

## ADDED Requirements

### Requirement: 验证面含 UI 行为时须包含打开 UI 的检查

验证规划时 SHALL 判定验证面是否包含 UI 行为，判定 SHALL 基于可核验事实信号，SHALL NOT 依赖自由判断。可核验信号（任一命中即判定含 UI 行为）：

- **文件类型信号**：本次改动文件集合中存在视图/样式承载文件（如 `.html`/`.css`/`.scss`/`.less`/`.vue`/`.svelte`，或 TSX/JSX 组件文件）；
- **验证目标信号**：变更目标、任务卡或修复描述以渲染、布局或交互行为为验证对象。

判定为含 UI 行为时，验证阶段 SHALL 在 AI 可驱动的环境中至少运行一次打开 UI 的检查（真实环境优先，按既有分层规则；模拟 UI 同样计为打开 UI）。该检查触发既有「打开 UI 须留存非空截图」义务。

当打开 UI 的检查因环境受限（部署不可达、输入不可模拟等）无法在本轮运行时，验证报告 SHALL 以显式 limitation 条目留痕：写明受限原因与受阻层，SHALL NOT 静默跳过，且 SHALL NOT 把非 UI 检查表述为覆盖 UI 行为。

#### Scenario: 文件类型信号命中

- **WHEN** 本次改动文件集合含视图/样式承载文件（如一个弹层定位修复改动了 `.css` 文件）
- **THEN** 验证阶段包含至少一次打开 UI 的检查并留存截图
- **AND** 不以类型检查/单测/规格校验全绿替代该检查

#### Scenario: 验证目标信号命中而文件类型未命中

- **WHEN** 改动文件集合不含承载文件，但变更目标明确以渲染行为为验证对象（如对渲染逻辑文件的修复，验证目标是弹层定位行为）
- **THEN** 判定步骤 SHALL 认定验证面含 UI 行为，验证阶段须包含打开 UI 的检查
- **AND** 同样不以全绿的非 UI 检查替代

#### Scenario: 环境受限时显式留痕

- **WHEN** 验证面含 UI 行为，但部署不可达或输入不可模拟导致打开 UI 的检查无法在本轮运行
- **THEN** 验证报告包含显式 limitation 条目：受限原因 + 受阻层 + 后续明确验证动作
- **AND** 不静默跳过，不把非 UI 检查表述为覆盖 UI 行为

#### Scenario: 非 UI 行为改动不受此强制约束

- **WHEN** 改动文件集合不含承载文件且验证目标不含渲染/布局/交互行为（如数据序列化逻辑修复，验证走解析器输出比对）
- **THEN** 该前置强制不触发，验证报告无需 UI 截图或 limitation 留痕
- **AND** 非 UI 检查（类型检查/单测/规格校验）照常满足验证要求

#### Scenario: 模拟 UI 也计为打开 UI

- **WHEN** 检查通过本地开发服务器页面、无头浏览器或带截图能力的渲染 harness 打开了界面
- **THEN** 该检查计为打开 UI，触发既有截图留痕义务
- **AND** 若模拟 UI 也不可达，则走「环境受限时显式留痕」场景
