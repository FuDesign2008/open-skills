## ADDED Requirements

### Requirement: 冲突残留标记判定 SHALL 以开闭标记配对为准

冲突残留标记的判定 MUST 采用配对判别：仅当同一文件同时存在 `^<{7,} `（开标记）或 `^>{7,} ` / `^\|{7,} `（闭/diff3 标记）时，纯 `^={7,}$` 命中行才判定为真残留；纯 `=` 行单独出现（如许可证标题下划线、Markdown 排版分隔线）MUST 判定为误报放行，不阻断流程。`^<{7,} ` / `^>{7,} ` / `^\|{7,} ` 三类真标记 MUST 仍被独立捕获（含 diff3 `||||||| base` 形态）。

#### Scenario: 纯等号分隔线判为误报

- **WHEN** 扫描命中某文件仅含 `===============` 纯等号行（第三方许可证标题下划线或 Markdown 分隔线），且该文件无任何 `^<{7,} ` / `^>{7,} ` / `^\|{7,} ` 命中
- **THEN** 系统判定误报并放行（Phase 0 不 abort、Phase 8 不禁止合并），报告中记录误报识别结果

#### Scenario: 配对标记存在时判为真残留

- **WHEN** 同一文件同时命中 `^<{7,} ` 开标记与 `^={7,}$` 分隔行
- **THEN** 系统判定为真实冲突残留，按原流程阻断（Phase 0 abort / Phase 8 禁止合并）

#### Scenario: 真实冲突标记仍被捕获

- **WHEN** 文件含标准 `<<<<<<< ` / `>>>>>>> ` 标记或 diff3 `||||||| ` base 标记
- **THEN** 无论是否伴随纯等号行，均判定为真残留

### Requirement: 残留判定标准 SHALL 在全部消费方保持一致

残留标记配对判别标准 MUST 在所有消费同一正则的防线上一致生效，包括 release 收尾侧（Phase 0 worktree 扫描、Phase 8 合并前门控、ff cherry-pick 流程的残留扫描、pre-commit hook）与冲突解决侧（单文件即时校验、累计清单扫描、提交前门控）。任一消费方 MUST NOT 保留「命中即残留」的旧判定语义。

#### Scenario: 两处消费方对同一文件行为一致

- **WHEN** 同一含纯等号分隔线的文件分别被 release 收尾扫描与冲突解决提交前门控扫描
- **THEN** 两处均判定误报放行，判定语义一致

#### Scenario: 消费方不残留旧判定语义

- **WHEN** 修改完成后全库检索残留正则的使用点
- **THEN** 每个使用点的判定均符合配对判别标准，无「命中即阻断」的旧语义残留
