## Context

`renderReviewPage` appended a paragraph link titled 证据留痕 whenever the review data carried an `evidencePath`. The explanation page is generated by the same renderer that already emits the shared navigation block, and the acceptance entry page lists the evidence page as a link card. The bottom link was a second, weaker path to the same target.

## Goals / Non-Goals

**Goals:**

- The review page ends after the problem/cause/fix sections.
- The evidence page remains reachable from the entry page and the navigation block.

**Non-Goals:**

- Removing the evidence page or its entry-page link card.
- Changing the standalone `goal-driven-workflow` review page, which has its own contract.

**Decisions**

- Drop the `evidencePath` branch from `renderReviewPage` and the now-unused `.evidence-link` rule; the shared navigation keeps the evidence page one click away.
- Lock the new behavior with a renderer assertion (no `证据留痕` link even when `evidencePath` is supplied) and a skill-contract assertion.
- The review JSON input may keep or omit `evidencePath`; the renderer ignores it.

## Risks / Trade-offs

- [A reader expects the evidence link on the review page] → The shared navigation and the entry page link card sit one click away; the review page stays focused on the explanation.

## Migration Plan

Regenerate existing review HTML pages. Rollback is reverting the renderer and the skill sentence.
