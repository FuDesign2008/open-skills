## Why

`merge-discipline` currently asks human preference questions one at a time, mid-flow: Part B asks "rebase?", Part C asks "run coverage?", Part R asks "full / light / skip?", Part D asks "squash?", and Part D's sync step offers branch deletion. A single merge can therefore stall four or five times, each time after a slow step (rebase, coverage run, review) has already run. Most of these answers do not depend on the output of earlier steps — they depend only on repository state that can be read up front (commit count, BEHIND/CONFLICTS, preference lines in `AGENTS.md`). Asking them late wastes turns and breaks the user's flow.

## What Changes

- Add a **Merge decision sheet** to `merge-discipline`: on merge intent, run a **read-only preflight** over Parts A/B/C/R/D, collect every pending human *preference* decision, ask them in **one batch form** (each item with options + Recommended + one-line rationale), then execute A→B→C→R→D consuming the sheet answers without re-asking.
- Sheet items (included only when human input is needed): archive skip (only if Part A would block), rebase confirm (BEHIND>0 or CONFLICTS>0), coverage run/skip (preference `ask`), review full/light/skip (preference `ask`), squash/no-squash (unless the collapse pre-check applies), optional delete-source-branch after merge.
- An **empty sheet** (every preference resolves without asking) proceeds straight to execution with no prompt.
- **Mid-flight failures stay separate pauses**, not sheet items: Part R fail / round cap, coverage below threshold / crash, rebase conflict stuck, post-merge ancestor MISSING, Part A block with no skip.
- After a rebase rewrites the tip, Parts C/R/D re-run their *detection* as today, but already-answered sheet items are not re-asked unless a new mid-flight failure appears.
- Add an **explicit carve-out**: the merge decision sheet is exempt from `clarifying-question-discipline` one-question-per-turn (merge gates are not a clarify interview). `clarifying-question-discipline` itself is **not** changed.
- Add a Part B requirement to the main spec (rebase confirm exists today only in the skill body) that includes sheet consumption.
- Modify existing requirements so "ask / wait" wording consumes sheet answers when present: coverage gate preference, Part R preference resolution, Part D squash decision, Part D workspace sync (optional branch deletion).
- Sync one descriptive reference in `workflow-contract-sync` (pre-merge checklist item "asked the user when `ask`") so it accepts sheet-based asking.
