## Context

主 spec 已按本变更写入。决定与执行分开，避免 `jira-status-lifecycle` 与 `jira-status-writeback` 互相依赖。

## Goals / Non-Goals

**Goals:**

- 在名下且为「待处理」时，分析前改为「解决中」；失败则不分析。
- 合并进目标分支后，在名下则改为「已修复」；失败则保留合并、生命周期不算完成，修复评论仍写。
- 会话用户解析失败不等同于「不在名下」。
- 不在名下只告知、不改状态。
- 不自动改「验证通过」「关闭」。

**Non-Goals:**

- 不撤销已完成的合并。
- 不把修复评论并进状态流转调用。

## Decisions

1. 技能名 `jira-status-lifecycle`。依赖单向：宿主和回写技能依赖它，它不依赖回写技能。
2. 规范状态名是「待处理」「解决中」「已修复」，并接受同义状态。分类交给调用方，矩阵只接收 `todo` / `in-progress` / `fixed` / `other`。
3. 身份未知在分析前停止；在合并后不流转、不把工单当成别人的、评论仍写、生命周期不算完成。

## Risks / Trade-offs

- 旧句子「失败不阻断收尾」已改为「合并不撤销，生命周期不算完成」。
- 代理模式若仍把全部 Jira 流转当人工，分析前认领会停住。本变更只把这两次开发侧流转放出。
