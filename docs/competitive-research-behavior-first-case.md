## 一、两起编辑器缺陷（脱敏）

两起都是「用户能看见的编辑行为」。调研时如果先抄实现，会对齐错误目标。

### 1.1 软换行行首按空格

现象：段落软换行后，在第二行行首按空格，视觉上没有变化。空格挂在上一行行尾，不参与断行。

行为层（评论转述，后经实现对照）：竞品是「下一字被挤到下一行，空格留在可见位置」，不是「空格留在行尾」。

实现层（登录后读计算样式和脚本，两家不同）：

| 竞品 | 机制 | 数据层 |
|------|------|--------|
| Competitor A | CSS `white-space: break-spaces`，不做不换行空格转换 | 普通空格 |
| Competitor B | 自绘渲染层把普通空格换成 U+00A0，导出路径再转回 | 普通空格 |
| 公开编辑器库 | `pre-wrap` 与 `break-spaces` 双声明，旧浏览器停在 `pre-wrap` | 普通空格 |

方案从「数据层写入不换行空格」收到「`break-spaces` + 能力检测，不支持则回退 `pre-wrap`」。放弃理由是搜索、复制、导出会带上不换行空格。

同一次实验里的操作失误：

1. 光标不在预期位置，测试文本插进正文中部。
2. 连续撤销被页面脚本挡住，批量按键没有生效。
3. 该产品的撤销快捷键不是 `Ctrl+Z`。早期把「快捷键没反应」当成「撤销无效」。
4. 改成单步撤销，并在每步之后看截图，页面才恢复。

### 1.2 引用块内按 Tab

现象：引用块内、第一个字符前按 Tab 没有可见变化；之后转成列表时，缩进按按过 Tab 的次数出现。

自动化第一次结论是错的：一家提示不能缩进当前块，另一家连续按两次视觉不变。据此推断两家都不支持引用内 Tab 缩进。

人眼纠正：两家都会做出可见缩进。自动化误差是自绘光标。`Home` 没有进入引用块，Tab 作用在块外段落上。

既有实现：渲染过滤故意丢掉引用内段落的缩进，所以模型里有缩进、画面上没有。转列表时再把残留缩进换算成列表层级，隐藏缩进延迟漏出来。

人眼确认竞品有可见缩进之后，改为放行该缩进样式。上线后再发现：多次 Tab 产生多级缩进，一次退格把全部缩进清零。原因是退格处理在偏移为 0 时重置整段样式，抢在逐级减少之前。修复是缩进大于 0 时把退格交给逐级减少。

## 二、经验对照

| 原文经验 | 现在写在哪 | 还缺什么 |
|----------|------------|----------|
| 先记用户动作和可见结果，再看实现 | 步骤 2 第 1–3 层；端到端流程第 3 步和精简路径的「一次一手检查」都先写行为记录，再进入五步取证 | 已对齐。取证不再是默认的第一步 |
| 自绘光标上，自动化按键要先证明光标在目标上 | 步骤 2.0：按键算数之前光标在目标上，记下的结果是目标处看到的结果；「没变化」仍不能单独当结论 | 已覆盖插错位置。不另写「必须截图、禁止批量按键」 |
| 第三方编辑器里单步操作、逐步确认，不批量按键或批量撤销 | 不写入技能 | 这是上一行的做法，随页面而变。快捷键差异同样不单独立项 |
| 证据要标明来源：人眼、自动化、转述 | 步骤 2.0 三档来源；行为表和证据条目模板（reference §1.4）都有来源档 | 已对齐。来源档与 E1/E2/E3 并列 |
| 采用行为后查边界：重复、退一级、归零、与已有行为的交互 | 步骤 2 第 2 层；精简路径在「将采用该行为」时纳入 | 已覆盖。引用内多次 Tab 再逐次退格，就是这一层的实例 |
| 设计取舍要写推荐、理由、被放弃的替代 | 步骤 3 三档映射：照搬、改写、明确不抄 | 已覆盖。「数据层不被不换行空格污染」是当时的自身约束，不是一条通用规则，不应再抽成铁律 |
| 具体 CSS 值、产品名、工单、需登录链接 | 故意不进技能 | 公开仓库的脱敏门禁会拦截工单号。这些留在本地原文 |

## 三、这次补进技能的范围

补进 `competitive-research` 2.0.1 的是三处对齐，不是操作手册：

1. 端到端流程第 3 步和精简路径的「一次一手检查」先完成行为记录，再进入实现取证。
2. 证据条目模板增加来源档，与 E1/E2/E3 并列。
3. 自绘编辑器上，自动化按键算数之前光标在目标上，记下的结果是目标处看到的结果。

单步按键、截图、禁止批量撤销、某个产品的撤销快捷键，不写进技能。
