# goal-driven-* 系列的 Intake 深度问题分析

> 「为什么 /goal-driven-queue 和 /goal-driven-workflow 与我核对的问题不如 /solve-workflow 时细致？」
> 本文基于一次真实工作流会话的第一手对照体验（两种 skill 系列在同一天、同一项目、同一执行者上先后使用），分析结构性根因并给出改进建议。

---

## TL;DR

不是纪律缺失，是**结构激励相反**：solve-workflow 把提问视为对齐的投资（每阶段出口停等，模板强制摊开理解）；goal-driven-* 把提问视为长跑的成本（「一次确认」闭合访谈，`§B` 自答优先级表激励把问题转化为假设记录）。五个结构性根因中，最关键的是 **「一次确认」的粒度** 和 **自答假设的影响分级缺失**。改进方向：人在场时升级为逐决策提问、高影响假设强制提问、冻结决策表旁边强制列出「被自答的决策点」。

---

## 1. 现象（实拍对照）

同一会话中两种 skill 的提问与确认行为统计：

| 维度 | solve-workflow（MR 分析轮） | goal-driven-queue（守卫轮） |
|---|---|---|
| 用户参与的确认事件 | **6 次**（阶段 1/3/4/5/7/8 各出口） | **2 次**（1 个问题 + 1 次卡片批准） |
| 提问聚焦度 | 每次一个具体决策（修复对象 4 选 1、方案 3 选 1、审查裁决、计划确认） | 一次「守卫 vs MR !3」后，其余决策全部自答冻结 |
| 结构化摊开 | 每阶段模板强制：重述/要素/疑问、方案对比表、审查报告、计划变更清单 | 紧凑任务卡：冻结决策表（**答案清单**，非问题清单） |
| 用户可纠正的时机 | 每个阶段出口（理解错误在下一步之前暴露） | 仅 intake 一次 + 验收一次（理解错误要等验收才暴露） |
| AI 自答的决策 | 几乎没有（无自答出口） | 守卫条件设计、埋点命名、验证方式、单测策略等 4-6 项 |

**实际代价的实拍案例**：守卫轮 intake 时，AI 假设「MR !3 可信且会落地」并把守卫定位为「过渡防御」冻结进卡片。用户批准后，AI 在后续输出中依然基于该假设行事——直到用户主动质疑「MR !3 未必可全信，你需要审视该 MR」，才被迫返工一轮（审视 MR !3 → 发现 open 3 个月无人 review → 守卫定位返工为「独立防线」→ 修订卡片）。**如果 intake 时问了「MR !3 的可信度/状态如何？」这个一次性的问题，用户大概率当场说出实情，整个返工可避免。**

## 2. 根因分析

### 根因 1：确认事件数量——「一次」对「每阶段」

solve-workflow 手动模式的 Quick Reference 表**逐阶段强制停等**（⛔ 出现在 1/3/4/5/7/8 每个出口），且每个出口有必选输出模板。goal-driven-queue 的 Stage 1 明文要求「Confirm condition + budget with the human **once, now**」——"once" 是设计意图：一次批准事件闭合整个访谈，之后就是无人值守跑。Stage 2/3 天然 auto-advance。

**核对粒度在规程层面就差一个数量级**，与 AI 的自觉无关。

### 根因 2：纪律的激励方向相反

两者都声明遵循 `clarifying-question-discipline`（一次一个最关键问题直到雾毕业）——字面一致，但配套机制相反：

- solve-workflow **没有自答出口**：问题只能问人（`clarifying-question-discipline` 的 hard discipline + investigation-first 也只是「先查再问」，查不到仍要问）。
- goal-driven-* 的 `§B` runtime self-answer 优先级表（**契约 → 可调查事实 → 保守默认**）是一条制度化的自答通道：任何决策先走这三梯，走到底才 clean stop。「可逆低影响」的判断标准由 AI 自己打分——而 AI 系统性倾向不打扰（把「保守默认」当作万能安全阀）。**纪律允许提问，结构激励不问。**

### 根因 3：输出模板的信息压缩

- solve-workflow 的每阶段模板把 AI 的理解**摊开**给用户：阶段 1 必须输出「重述 + 要素 + 疑问」，阶段 3 必须输出完整方案对比表——用户核对的是「AI 的理解」，纠错成本低。
- goal-driven 的任务卡是**无人值守优化的紧凑格式**：冻结决策表本质是「答案清单」。用户看到的不是「AI 在哪些点上不确定、为什么这样选」，而是「AI 已经替你决定了这些」——要纠正需要逐行审表，且在「批准并开跑」的流程惯性下，逐行审表的发生率很低。

### 根因 4：「一次确认」的心理学——确认粒度与审阅深度成反比

一次大确认（卡片批准 + 开跑三合一）与多次小确认：确认的信息量越大、格式越紧凑、夹带操作决策（「跑不跑」）越多，用户单点审阅深度越低（确认疲劳 + 顺序效应）。solve-workflow 的小确认每次焦点单一，用户实际参与度反而高。实拍中用户对守卫卡片的「批准修订并开跑」是一次三合一决策——冻结决策表中的 F3-F6（守卫条件、埋点、验证方式）连被单独审视的机会都没有。

### 根因 5：无人值守假设对「人在场」场景的泄漏

goal-driven-* 的价值主张是「人不在场也能跑」（detach-run-accept 循环），整套 intake 都为缺席者设计（冻结文本代替在场批准）。但用户的真实使用模式常常是**人在场**（实拍的守卫轮，用户全程在线即时响应）。skill 没有区分「在场的手动模式」与「缺席的 detach 模式」的 intake 深度——Stage 1 无论人是否在场都走同一条「一次确认」通道。solve-workflow 的手动模式天然适配在场场景，goal-driven 在此场景下是拿缺席模式服务在场用户。

### 根因 6（次级）：缺乏「提问预算」的下限约束

solve-workflow 的阶段出口相当于强制了最小交互轮次（≥5 轮）；goal-driven 只设上限思维（caps 是「最多跑多少」），没有 intake 提问的下限。AI 在「能不问就不问」的自答激励下，提问数量收敛到合规下限 1。

---

## 3. 本质：设计取舍，但被一刀切了

这不是缺陷而是取舍：goal-driven-* 服务「无人值守」，提问是长跑的阻塞成本，结构性地最小化提问是正确的**缺席设计**；solve-workflow 服务「逐步对齐」，提问是投资。问题在于当前实现把取舍**一刀切**：无论人是否在场、无论假设影响多高，一律走最小提问通道。改进不需要牺牲无人值守价值，只需要在「人在场」与「高影响假设」两个维度上恢复提问。

---

## 4. 改进建议

按落地成本从低到高排列，均可直接落到 skill 文本：

### 建议 1：影响分级提问（改 `intake-interview-discipline` §A/§B 或各 host 的 Stage 1）

intake 阶段的自答假设按 **impact-if-wrong** 分级：高影响假设（守卫定位依赖上游 MR 可信度、验证策略、对外契约等）**必须提问**，不得默认冻结；仅低影响（命名、临时格式、可逆小选择）走保守默认 + 账本。落点：`§B` 优先级表的梯 3 前插入「高影响假设 → 升格为 intake 提问」的闸门，并在 §A 冻结前复核一遍所有自答项的影响分级。

### 建议 2：在场感知的 intake 深度（改 goal-driven-queue Stage 1 / workflow Stage 1）

trigger 语义区分两档：
- 用户声明离开（「我下班了」「无人值守」「自动跑」）→ 现行「一次确认」+ 全账本模式（保持不变，这是该系列的核心价值）；
- 用户在场（默认，或明示「我在」「手动」）→ intake 升级为**逐决策提问**：关键决策一次一个问完（遵循 clarifying-question-discipline），确认事件按决策数自然增加，而非一次性闭合。

### 建议 3：冻结决策表旁强制列「问题清单」（改 Task Card 模板）

卡片模板在 Frozen Decisions 表之外增加一段「**Decisions I made for you**（被自答的决策及其影响分级）」——把 `§C` 账本里本应事后审的条目**前移到确认时刻**。用户批准卡片时一眼看到「AI 替我决定了哪些」，当场可推翻，而不是验收时才发现。这是对「答案清单」信息压缩的最小修正。

### 建议 4：拆分「批准」与「开跑」（改 Stage 1 第 3 步）

「Confirm condition + budget **once**」拆为两个独立确认事件：①卡片内容批准（此时必须展示建议 3 的问题清单）；②开跑指令（用户明确说「跑」才进入 Stage 2）。消除三合一确认的流程惯性。

### 建议 5：intake 输出采用 solve-workflow 阶段 1 模板打底（改 Stage 1 输出格式）

卡片之前的中间产物强制输出 solve-workflow 阶段 1 的三段式（重述 / 关键要素 / 待确认问题）——重述暴露理解偏差，要素划定边界，问题清单驱动提问。卡片成为三段式的**产物**（浓缩）而非**替代**。用户先看摊开的理解再批准浓缩卡片。

---

## 5. 一句话总结

**goal-driven-* 不细致，是因为它的结构把「问人」定价为成本、把「自答」定价为效率；改进的关键不是增加纪律条文（纪律已经在），而是在「人在场」和「高影响」两个维度上，让提问重新比自答便宜。**
